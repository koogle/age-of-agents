# Reset seed review

Scope: rename the Rust HUD action to **Reset game** and collect an optional decimal island seed using platform text controls. The browser uses its native prompt; desktop uses `tinyfiledialogs`. Both offer a progress-loss warning, confirmation, cancellation, and validation without custom caret/clipboard handling. Blank requests a random island. Explicit seeds retain the entire unsigned 64-bit range.

The old four-second confirmation timer and HUD model flag are removed. One small module owns input and validation; the existing world source accepts `Option<u64>` and delegates generation to `GameWorld::generate` or the existing `POST /reset?seed=` endpoint. Local reset also clears fractional tick accumulation and previous command results. HTTP reset failures produce a toast, and reset no longer rewinds the server's monotonic snapshot sequence filter.

Thermonuclear review: no simulation rules, resource costs, persistence paths, NPC behavior, or spatial claims changed. The native-only dialog dependency earns its place by supplying standard platform text editing without a custom widget framework. Every changed client source file stays below 1,000 lines. Mouse and touch use the same reset action; cancel never calls reset. Seed parsing occurs before world mutation, and the existing server persists a replacement before applying it.

Validation: all 119 integrated workspace tests pass (13 server, 31 client, 75 game), including seed boundaries and clean local reset. Formatting, strict native/WASM Clippy, native workspace release build, browser release build, generated-JS syntax, and diff whitespace checks pass. Rebuilt `web/pkg`. Chromium exercised hosted cancellation, seeds 0/42/u64 max, invalid retries, repeatable terrain, blank/random reset, HTTP failure, and mobile touch at DPR 2. Browser-local mode reproduced terrain for the same seed without sending HTTP resets. No browser page errors.
